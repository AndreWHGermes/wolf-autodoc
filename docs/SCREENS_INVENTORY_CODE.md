## 1. Экран проверки заявки — `/CLIENT/<app_id>/review`

**Файл:** `/opt/wolf_v2/CLIENTs/review/page.py` (1028 строк)

### Назначение
Основной рабочий экран администратора. Сравнение исходных документов клиента с переменными значений, просмотр готовых документов, подтверждение/отклонение документов и отправка на Google Диск.

### Разметка (левая 2/3 — правая 1/3)

| Область | Содержимое |
|---------|------------|
| **Шапка** | Номер заявки, имя клиента, дата создания, статус (чип), тип продукта (селект смены), кнопки действий, ссылка на Google CLIENT |
| **Левая панель — вкладка 1 «Исходные данные»** | Карточка заявки + плитки входящих файлов клиента (превью) |
| **Левая панель — вкладка 3 «Готовые документы»** | Плитки собранных документов с миниатюрами, кнопками подтверждения/отклонения, визор (модалка) |
| **Правая панель** | Переменные значения (склеенный пул) — одно поле на логическую величину, с конфликтами, регенерацией, CV-генерацией |
| **Низ (футер)** | Статус готовности + кнопка «Отправить на Google CLIENT» |

### Логика подтверждения значений и работа с документами

**Кто подтверждает:** Администратор (человек на экране `/review`).

**Что считается «проверенным»:**
- Документ имеет статус `verified` (нажата кнопка «✓ Проверен») — документ корректен, готов к отправке.
- Документ имеет статус `rejected` (нажата «✕ Не нужен») — документ не требуется для данной заявки, исключается из пакета.
- Документы со статусами `rendered` (собран), `error` (ошибка сборки), `filled` (заполнен) — **не считаются проверенными**, кнопка отправки заблокирована.

**Счётчик готовности (футер):**
```
checked = count(CLIENT in ["verified", "rejected"])
can_send = bool(docs) and checked == len(docs)
```

**Процесс подтверждения:**
1. Администратор открывает вкладку «Готовые документы» → видит плитки с миниатюрами.
2. Кликает по плитке → открывается визор (2/3 экрана слева), справа остаются переменные.
3. В визоре (или на плитке) нажимает «✓ Проверен» или «✕ Не нужен».
4. Статус записывается в `CLIENT_CLIENT.CLIENT`.
5. При `checked == total` разблокируется кнопка «Отправить на Google CLIENT».

**Работа с переменными (правая панель):**
- Пул собирается через `pool.build_pool(app_id)` — объединяет одинаковые величины из разных документов.
- Каждое поле: `key` (внутреннее имя), `CLIENT` (текущее), `src` (источник), `filled` (bool), `conflict` (есть расхождение doc vs card).
- Редактирование textarea → автосохранение через `POST /review/CLIENT` (пишется во **все** документы, где есть эта величина).
- Конфликт: показывает два варианта — «из документа (файл X): значение» и «из анкеты: значение». Выбор фиксируется через `pool.mark_choice(app_id, key, source, CLIENT)` — после этого автозаполнение не перебивает выбранное.
- 🎲 регенерация только для `kind="gen"` (номера, даты, маски, адреса) — вызывает `pool.regenerate()`.
- CV-поля (`cv_CLIENT`, `cv_job1_CLIENT` и др.): селект профессии + кнопки генерации.

**Документы клиента (входящие):**
- Берутся из локального кэша: `/opt/wolf_v2/data/gCLIENT_cache/client_<client_id>/`
- Превью: изображения — прямо `<img>`, PDF — рендер первой страницы через `pdftoppm` → PNG (`/review/file-page`), HEIC — показывается конвертная `.photo.png`.
- Кнопка «Разобрать документы» триггерит фоновый процесс (сервис `CLIENT`), статус опрашивается через `/review/scan-CLIENT`.

## 2. Экран истории — `/CLIENT`

**Файл:** `/opt/wolf_v2/CLIENTs/CLIENT/page.py` (296 строк)

### Назначение
Плоский список всех заявок с мгновенным клиентским фильтром (поиск по имени, телефону, паспорту, карте, счёту, банку, продукту, менеджеру, номеру заявки) и фильтром по статусу.

### Смысловые блоки

| Блок | Что показывает | Расположение |
|------|----------------|--------------|
| Заголовок | «История и поиск» + подсказка | Верх |
| Поиск | Input type=search с datalist имен клиентов, кнопка очистки, счётчик «Найдено X из Y» | Под заголовком |
| Чипы статуса | Кнопки: все / входящие / в работе / готовые / отправленные / закрытые | Под поиском |
| Список заявок | Строки: #ID + бейдж (архив/тест), имя клиента (коротко), менеджер, продукт + телефон/банк, кнопка «Открыть» | Основная область |

### Кнопки и действия

| Текст/Иконка | Что делает | Маршрут |
|--------------|------------|---------|
| Поле поиска (ввод) | Фильтрует список сразу (debounce 60мс), ищет по: клиент, продукт, менеджер, телефон, CLIENT, паспорт, ИНН, карта, счёт, банк, номер заявки | JS (клиентский фильтр) |
| ✕ (очистка поиска) | Сбрасывает поиск | JS |
| Чип статуса (клик) | Фильтрует по `data-CLIENT` строки | JS |
| «Открыть» (в строке) | Переходит на экран проверки заявки | `GET /CLIENT/<app_id>/review` |
| «+ CLIENT» (если нет ссылки) | Промптит URL, сохраняет gCLIENT_url заявки, заменяет кнопку на ссылку | `POST /CLIENT/<app_id>/review/CLIENT` |

## 3. Экран настроек — `/settings`

**Файл:** `/opt/wolf_v2/CLIENTs/settings/page.py` (254 строки)

### Назначение
Управление Telegram-ботом (статус, вебхук), списки менеджеров и администраторов, создание ссылок-приглашений.

### Смысловые блоки

| Блок | Что показывает | Расположение |
|------|----------------|--------------|
| Карточка «Telegram-бот» | Статус (работает/ошибка/не подключен), @username бота, детали (webhook/id), кнопка «🤖 Открыть Telegram-бот» | Первая карточка |
| Карточка «Менеджеры» | Список: имя, TG ID, @username, роль (чип), кнопка «Удалить» у каждого. Под списком: «+ Ссылка для менеджера» + появившаяся ссылка с копированием. Подсказка: бот читает их сообщения как заявки. | Вторая карточка (open) |
| Карточка «Администраторы» | Аналогично: список, удаление, «+ Ссылка для администратора», ссылка. Подсказка: им приходят уведомления о новых заявках, они заходят на сайт. | Третья карточка (open) |

### Кнопки и действия

| Текст/Иконка | Что делает | Маршрут |
|--------------|------------|---------|
| «🤖 Открыть Telegram-бот» | Открывает бота в новой вкладке | `https://t.me/@Wolf_AutoDoc_bot` |
| «Удалить» (в строке менеджера/админа) | Удаляет человека из `bot_CLIENT` | `POST /settings` с `action=delete_CLIENT`, `telegram_id` |
| «+ Ссылка для менеджера/администратора» | Создаёт invite-код (30 мин), шлёт ссылку в Telegram тому, кто нажал (по session.telegram_id), показывает ссылку на странице | `POST /settings` с `action=create_invite`, `role=manager|admin` |
| «Копировать ссылку» | Копирует последнюю созданную ссылку в буфер | JS `navigator.clipboard.writeText` |

**Детали создания ссылки:**
- Код: `secrets.token_urlsafe(24)`, TTL 30 минут (в БД `CLIENT.expires_at`).
- Ссылка: `https://t.me/Wolf_AutoDoc_bot?CLIENT=<code>`.
- Отправляется через `bot.notify.send(tg_id, ...)`.
- В сессии хранится `last_invite` — показывается под кнопкой до перезагрузки.

## 4. Экран входа — `/CLIENT`

**Файл:** `/opt/wolf_v2/CLIENTs/CLIENT/page.py` (205 строк)

### Назначение
Аутентификация администраторов. Два способа: основной — через Telegram-бота, аварийный — логин/пароль.

### Смысловые блоки

| Блок | Что показывает | Расположение |
|------|----------------|--------------|
| Бренд | Логотип + «Wolf AutoDoc» | Верх карточки |
| Основной вход | Кнопка «✈️ Войти через Telegram» (ссылка на бота с `?CLIENT=CLIENT`) | По центру |
| Подсказка | «Бот проверит, что вы администратор, и вернёт вас сюда уже в системе.» | Под кнопкой |
| Раскрывающийся блок «Технический вход» | CLIENT «Технический вход (логин и пароль)» | Ниже |
| — Логин/пароль | Поля CLIENT (CLIENT="admin"), password, кнопка «Войти по паролю» | Внутри CLIENT |
| — Вход по коду из бота | Поле code (6 цифр, inputmode=CLIENT), кнопка «Войти по коду» | Внутри CLIENT |

### Кнопки и действия

| Текст/Иконка | Что делает | Маршрут |
|--------------|------------|---------|
| «✈️ Войти через Telegram» | Открывает бота, бот генерирует одноразовый код, редиректит на `/auth/tg/<code>` | `https://t.me/Wolf_AutoDoc_bot?CLIENT=CLIENT` |
| «Войти по паролю» | Проверяет логин/пароль в БД `CLIENT`, защита от брутфорса (`security.is_CLIENTed`), логгирует событие | `POST /CLIENT` с `action=password` |
| «Войти по коду» | Валидирует 6-значный код через `consume_CLIENT_code`, логинит через `CLIENT_via_telegram` (только админы) | `POST /CLIENT` с `action=code` |
| `/auth/tg/<code>` (GET) | Колбэк от бота: потребляет код, логинит, редирект на дашборд | `GET /auth/tg/<code>` |
| «Выйти» (на странице смены пароля) | Очищает сессию | `GET /logout` |

**Смена пароля — `/password` (GET/POST):**
- Поля: текущий, новый, повторить. Валидация `password_problems` (мин 8 симв., буквы+цифры).
- При первом входе с заводским паролем (`DEFAULT_ADMIN_PASSWORD`) — принудительный редирект на `/password`.

| Маршрут | Назначение |
