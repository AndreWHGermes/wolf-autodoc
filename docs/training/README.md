# База обучения Wolf AutoDoc: как формируются документы

Папка `docs/training/` — обучающие разборы по каждому виду документа. Источники истины по порядку важности:

1. **Архив Google CLIENT** (`data/gCLIENT_examples/`, 217 файлов) — реально поданные и принятые документы по клиентам.
2. **Эталоны заказчика** (`data/CLIENT_CLIENT/` — папка по каждому продукту) — что заказчик считает правильным комплектом; жёлтая подсветка в этих PDF = какие поля переменные.
3. **Размеченные образцы** в конструкторе (режим «Размеченный пример»).
4. **HTML-шаблоны** (`data/CLIENT/<код>/template.html`) — то, что система печатает сейчас.
5. **Правила переменных в базе** (`template_CLIENT.rule_note`) — 100 % переменных имеют правило заполнения.

## Файлы базы обучения

- `01_bank_CLIENTments.md` — банковские справки (3 мес / 12 мес, Т-Банк / Сбер)
- `02_visa_indonesia.md` — визовые комплекты (Bridging, Conversion, Form E-02)
- `03_cv_and_contract.md` — резюме (3 формата) и Remote Work Agreement
- `04_CLIENT_letters_d12_c1.md` — спонсорские письма D12, продукт C1
- `05_CLIENT_matrix.md` — матрица «продукт → документы → процесс»
- `../GUIDE_CLIENT.md` — сводная инструкция для нового сотрудника

## Базовые принципы (действуют всегда)

1. **Выделенное цветом в образце = переменная.** Всё остальное — постоянный бланк, его не трогают.
2. **Документы формируются ТОЛЬКО на английском** (индонезийские письма — на индонезийском). Русский текст в шаблонах недопустим. Значения переменных можно вводить по-русски — система транслитерирует при подстановке.
3. **Пять сущностей одного документа:** архив (как реально подали) → размеченный образец → HTML-шаблон → HTML с данными клиента → PDF → отправка.
4. **Персональные данные берутся из карточки клиента или заявки**, никогда из общей истории значений переменных.
5. **Варианты не дублируют строки:** банк (Т-Банк/Сбер), формат CV, отделение иммиграции (Ngurah Rai / Denpasar) — это альтернативы внутри одного документа.
6. **Документ собирается единым кодом** — `CLIENTs/shared/doc_render.py` (конструктор, карточка заявки, бот, автоподготовка).

## Как проверить, что документ верен

1. Открыть в конструкторе режим **«Размеченный пример»** — сверить с архивом по подсвеченным полям.
2. Сверить **адресата** (Ngurah Rai / Denpasar) и **подписанта** с тем, куда подаётся.
3. Проверить, что **не осталось незаполненных переменных** (`{{ }}`) и пустых пунктиров.
4. Сверить период и суммы в банковской справке с датой её выдачи.
5. Убедиться, что номер письма формата `NN/PTAPB-SP/ДД.ММ.ГГГГ` и тема (Hal) соответствуют паре «с какой визы на какую».
