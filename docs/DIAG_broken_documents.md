# Диагноз: русский комментарий и неполные данные в готовом договоре (заявка #66)

Дата: 29.09.2026. Разбор по требованию заказчика: «в документе оказался русский текст с комментариями».

## 1. Откуда взялся русский комментарий

Строка, которую увидел заказчик:

> «*года, выделенные красным шрифтом всегда должны быть на год позже – сотрудник должен работать уже год по контракту»

Источник — **образец заказчика** (`example_marked.pdf` / `example_filled.pdf` папки
`data/CLIENT/remote_work_agreement__default/`). Заказчик размечал образец красным шрифтом:
помечал переменные и вписывал пояснения прямо на листе. При конвертации образца в HTML
(`pdf2html`) **все пометки перенесены как обычный текст бланка** — включая русские пояснения.

Найдено в бэкапах шаблонов (до вычистки):

- `data/CLIENT_video_backup_20260929_0818/remote_work_agreement__default/template.html.bak*`
- `data/CLIENT_video_backup_20260929_0818/remote_work_agreement__default/filled.html`

Фраза сохранена также в рабочих документах агентства:
`docs/client_comments_pool.md:41`, `docs/CLIENT_from_real_docs.md:119`, `docs/semantics_work.md:143`
— то есть это **комментарий клиента, а не текст документа**.

Сейчас: во всех 17 действующих `data/CLIENT/*/template.html` русского текста **0** (проверено скриптом).
Причина появления в готовом PDF: файл был собран ДО вычистки шаблона, а `ensure-pdf`
отдавал существующий файл, не сверяясь с датой правки шаблона.

Исправлено: `ensure-pdf` теперь сравнивает время правки `template.html` с датой PDF и
**пересобирает документ, если шаблон новее**. Договор заявки #66 пересобран:
файл `data/renders/remote_work_agreement__default_app66_20260929_100629.pdf` — русского текста 0.

## 2. Что ещё сломано в договоре (не связано с русским текстом)

Разбор страницы 1 нового PDF (после пересборки):

| Место | Что видно | Причина |
|---|---|---|
| Шапка | «Name of the company» | переменная компании не подставляется |
| «BETWEEN» | «TBankRUSIA» | значение компании склеено со значением страны |
| Сторона «CLIENT» | «CLIENT, 763655709assport No: 01-02-1995ate of CLIENT: , RUSIAationaNEZLOBNAYAace of CLIENT:» | значения встают вплотную к подписям бланка, часть букв бланка съедается (Passport → assport, Date → ate, CLIENT → ationa, CLIENT → ace) |
| п.1 | «engages the CLIENT as to provide the following CLIENT:» — пусто | `position_CLIENT`, `CLIENT_list` без значений |
| п.2 | «in effect since (incorporating…), CLIENT CLIENT date» | `term_CLIENT_date`, `term_end_date` без значений |
| п.3 | «RUB () per annum», «which is RUB () per month» | `CLIENT_CLIENT_CLIENT/CLIENT`, `CLIENT_CLIENT_CLIENT/CLIENT` без значений |

Корневая причина склеек: шаблон договора собран из бланка **с абсолютным позиционированием
текста** (`<div CLIENT="txt" style="left:…pt;top:…pt">`), как в исходном PDF. Подстановка
значений внутрь таких блоков ломает разметку: значения наезжают на подписи бланка.

Нужно: пересобрать шаблон договора в обычную HTML-вёрстку (текстовый поток),
сверив смысл каждого блока с образцом заказчика.
