# Wolf AutoDoc — паттерны работы с документами (что берём в реализацию)

Источник: исследование практик PandaDoc, DocuSign CLM, Adobe Acrobat Compare, Dropbox Sign,
Clio Draft, PDFMonkey, плюс паттерны diff и pre-flight validation.

---

## 1. Оригинал и результат рядом

- **Основной режим — две колонки с синхронной прокруткой** и кнопкой «Отключить синхронизацию» (Adobe Acrobat side-by-side, GitHub diff).
- **Оверлей-переключатель (Таб)** — для узких экранов и быстрой проверки.
- **Diff-режим включается вручную:** красное — убрано, зелёное — добавлено, жёлтое — изменено. Не показывать всегда — это шум при полном совпадении.
- **Связные ленты** между колонками — для длинных документов; клик по ленте → список правок в этом диапазоне.

## 2. Откуда взято значение поля (важное для нас)

- У каждого поля — **метка источника**: «из паспорта», «введено вручную», «из продукта».
- Наведение → тултип: какой файл, какая страница, когда разобран. Клик → исходный скан открывается на нужной странице.
- **Цвет доверия:** из документа-подтверждения — уверенно; из распознавания — под проверку; введено руками — требует подтверждения.
- **Панель «Источники»**: список файлов со счётчиком «сколько полей взято» и статусом (использован / нет печати / не загружен).

## 3. Список документов пакета

- Статусы чипами: не создан · черновик · готов · на проверке · отправлен · ошибка.
- **Мультивыбор строк → плавающая полоса действий**: «Скачать ZIP · Отправить на Диск · Отметить готовыми». Без этого каждое действие дублируется в каждой строке.
- **Действие по состоянию строки:** «не создан» → «Собрать»; «черновик» → «Открыть редактор»; «ошибка» → «Повторить» с объяснением.
- Колонки: документ · шаблон · статус · версия · обновлён · действие.

## 4. Отправка в хранилище (Google Диск)

- Окно с тремя понятными частями: **цель** (папка клиента, показать путь), **имя файла** (шаблон имени), **сводка** (сколько файлов, размер).
- **Прогресс по каждому файлу**, не один общий спиннер: «3 из 5 · Паспорт ✅ · Справка ⏳ · Выписка ❌ нет доступа».
- При частичной ошибке: успешные сохраняются, по неудачным — «Повторить выбранные» и «Открыть папку».
- Файл с тем же именем **обновляется**, а не создаёт дубликат.

## 5. Версии

- Каждая пересборка — новая версия, старая не удаляется; в панели «Версии»: дата, кто, почему («ручная правка», «обновили данные клиента»).
- Метка «Текущая» и «Архив»; «Сравнить с предыдущей» → diff-режим; «Сделать текущей» → новая версия-копия.

## 6. Проверка перед отправкой (pre-flight)

- Кнопка отправки **выключена**, пока есть незаполненные обязательные поля; рядом счётчик и список: «не хватает 1 поля: Спонсор».
- При попытке отправки — проверка: обязательные поля, доступ к папке, предупреждения (не блокируют) и блокеры.
- «Исправить» ведёт фокусом к первому проблемному полю.

## 7. Уведомления

- Короткий отклик (3 сек): «Документ собран», «Сохранено на Диск» — с кнопкой «Открыть папку».
- Долгие операции — в панель задач с прогрессом, а не всплывашкой.
- Ошибка не исчезает сама: есть «Повторить».

## Порядок шагов пользователя в заявке (наш сценарий)

1. Открыть заявку → слева список пакета со статусами.
2. Выбрать документ «не создан» → «Собрать».
3. Центр: наш документ, вторая вкладка — реальный скан. Поля справа с меткой источника; клик по полю подсвечивает место в документе.
4. Править поля → центр обновляется.
5. «Сохранить документ» → фиксируется версия.
6. «Сгенерировать PDF» → отклик с прогрессом → файл готов.
7. «Отправить на Диск» → окно: папка клиента, список файлов с галочками → прогресс по каждому → «Готово, открой папку».
8. Статус документа: «отправлен»; документ остаётся доступен для повторной отправки.
