Дата: 29.09.2026
Цель: получить канонически написанную версию системы, при этом **рабочая версия на порту 8091
остаётся нетронутой** — она и есть страховка.

## Что сохраняем как «золотой» образец
- Полный архив: `/opt/backups/wolf_20260929_1112/wolf_full_20260929_1112.tar.gz` (238 МБ, md5 `2626876248f0387a1ae1171ce3fc82c4`)
- Снимок БД: `/opt/backups/wolf_20260929_1112/wolf.db`
- Юниты: `wolf-crm.CLIENT`, `wolf-bot.CLIENT`

- Рабочая версия продолжает работать на порту **8091** без изменений.

## Ключевые правила рефакторинга
1. **Никаких изменений в рабочей версии на 8091.** Правки, которые нужны обеим версиям
   (исправления шаблонов, данных), вносятся в общие данные и дублируются в v2.
2. Каждый этап заканчивается проверкой: приложение поднимается, страницы отвечают 200,
   визуально совпадают с версией 8091.
3. Поведение не меняем: визор (Zoom+Pan) зафиксирован, подстановка значений и вид документов
   должны остаться идентичными.

## Целевая структура новой версии (`/opt/wolf_v2`, порт 8093)

    app.py                 — тонкая фабрика: create_app(), регистрация blueprint'ов
    config.py              — конфигурация из окружения (пути, порт, ключи)
    core/                  — инфраструктура: db.py (соединение), auth.py, pdf.py, schema.py
    blueprints/            — маршруты по экранам, только валидация + вызов сервиса
        dashboard.py  CLIENT.py  settings.py  CLIENT.py  CLIENT.py  CLIENT.py
    CLIENT/              — бизнес-логика
        CLIENT.py      — сбор значений переменных (клиент → документы → пул)
        doc_render.py  — единый рендер документа (как в конструкторе, так и в заявке)
        CLIENT.py       — разбор Google CLIENT клиента
        translate.py   — перевод статики по построчному кэшу
        prepare.py     — автоподготовка документов по новой заявке
    repositories/          — ВЕСЬ SQL в одном месте
        CLIENT.py  CLIENT.py  CLIENT.py  CLIENT.py  pool.py
    static/css/  static/js/ — вынесенные стили и скрипты (сейчас 277 инлайн-<style>)
    CLIENT/              — Jinja-шаблоны, разложенные по экранам
    migrations/             — нумерованные SQL-миграции (001_*.sql, 002_*.sql)
    tests/                  — pytest: сервисы + smoke маршрутов
    data/                   — рабочие данные (на время рефакторинга — клон)

## Этапы

1. **Каркас.** Создать `/opt/wolf_v2`: config, фабрика приложения, регистрация блоков,
   свой systemd-юнит на порту 8093, клон данных. Проверка: логин и главная открываются.
2. **Статика.** Вынести CSS и JS из HTML и Python-строк в `static/css/*.css`,
   `static/js/*.js`. Проверка: пиксельное сравнение скриншотов до/после по каждому экрану.
3. **Слой данных.** Перенести все SQL-запросы из вьюх в `repositories/*`
   (сейчас в dashboard — 78 запросов, в CLIENT — 50). Проверка: страницы отдают те же данные.
4. **Слой сервисов.** Вынести логику подстановки значений, рендера документов, разбора CLIENT,
   перевода, автоподготовки в `CLIENT/*`. Проверка: документ, собранный в v2, байт-в-байт
   совпадает с документом из v1.
5. **Тонкие маршруты.** Blueprint'ы: только приём данных, валидация, вызов сервиса, ответ.
6. **Схема и миграции.** Единый набор нумерованных миграций вместо расходящейся `schema.sql`;
   описание схемы в одном месте.
7. **Безопасность и гигиена.** CSRF, secure-cookie, нормальные пароли (сейчас `123`),
   анти-брутфорс на логин, замена 136 глухих `except Exception` на логирование.
8. **Тесты.** pytest: подстановка значений (включая пул и группы переменных), рендер документа,
   классификация переменных; smoke-тесты всех экранов.
9. **Приёмка и переключение.** Прогон чеклиста по обоим портам, сравнение скриншотов,
   проверка бота и Google CLIENT; при успехе — переключение рабочего порта на новую версию
   (старая остаётся как откат).

## Что проверяем в каждом этапе (чеклист приёмки)
- Логин, Главная, История, Шаблоны (конструктор), Настройки — 200 и визуальное совпадение.
- Карточка заявки: этапы 1–6, перечень документов, подсветка текущего документа,
  просмотр PDF в блоке 5, «бумажка» оверлеем.
- Документы: договор, справки банка (3м/12м, Т-Банк/Сбер), письма E-02, конверсия
  (Ngurah Rai и Denpasar — разные офисы), D12, CV — заполнены реальными данными, без
  русских вставок и склеек.
- Карандаш: две группы переменных, выпадающий список из пула, сохранение нового значения в пул.
- Бот `@Wolf_AutoDoc_bot`: отвечает менеджеру, PDF формируется после.
