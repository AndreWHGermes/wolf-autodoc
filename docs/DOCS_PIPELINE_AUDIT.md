# Аудит: цикл «собрал документ → PDF → отправил на Google Диск»

Дата: 03.10.2026. Проверено по коду `/opt/wolf_v2` (без изменений в проде).

## Что уже работает

**Рендер документа** — `CLIENT/render.py`:
- `generate(CLIENT_id, template_id)` — полный цикл: значения из карточки клиента + сохранённые значения заявки → HTML → PDF. Возвращает `pdf_path, html, CLIENT, unfilled`.
- `render_pdf(html, base_dir, out_path)` — HTML → PDF через WeasyPrint; сам подставляет пути к картинкам шаблонов из статики.
- `doc_filename(CLIENT, CLIENT, ext, code)` — имя файла вида «Bank Statement 3 months (TBank) PETROV SERGEY 03.10.2026.pdf» — латиницей, как в папках клиентов на Диске.
- `unfilled(html)` — список незаполненных переменных. **Это готовый механизм проверки перед отправкой.**
- `warm_up()` — прогрев, чтобы первый документ собирался за ~0.3 с, а не 1.5 с.

**Запись на Google Диск** — `CLIENT/gCLIENT_write.py`:
- `upload_file(folder, path, name, mime, overwrite=True)` — загрузка **с обновлением существующего файла вместо дубля**.
- `upload_bytes(folder, data, name, mime, overwrite)` — для PDF, собранных в памяти.
- `upload_html_as_gdoc()` — HTML → Google Docs (редактируемый).
- `export_gdoc(file_id, 'pdf'|'docx'|...)` — экспорт Google-документа.
- `create_folder()`, `list_folder_contents()`, `find_file_in_folder()`, `resolve_folder_id()`.
- `_retry_on_quota()` — повторные попытки с задержкой на 403/429.
- Scope: `CLIENT.file` (робот видит и пишет только то, что ему расшарили).

**Хранение данных:**
- `CLIENT.gCLIENT_folder_url` — папка клиента на Диске.
- `CLIENT.gCLIENT_url` — папка заявки.
- `CLIENT_CLIENT`: `pdf_path`, `rendered_at`, `CLIENT`.

**Интерфейс:** в карточке заявки (`CLIENTs/review/page.py`) есть роуты `review/CLIENT`, `review/CLIENT`, `review/CLIENT` (сохранение ссылки на папку), `scan-CLIENT`, `file-page`, `file`. Есть `CLIENT/CLIENT.py` со статусом загрузки документов клиента.

**Тесты:** `tests/test_CLIENT.py` — 12 тестов на подстановку, транслит, даты, опциональные строки.

## Чего НЕ хватает (разрывы цикла)

1. **Реальной отправки файлов на Диск нет.** Роут `_send_to_CLIENT` в `app.py:610` только меняет статусы в базе (`sent`) и пишет событие — файлы на Диск не загружаются. `gCLIENT_write.upload_file()` из интерфейса не вызывается нигде.
2. **Нет кнопки «Сгенерировать PDF» в карточке заявки.** `render.generate()` вызывается только из скриптов и конструктора шаблонов (`CLIENTs/CLIENT/page.py:2589, 2627`).
3. **Нет связи «документ заявки → готовый PDF»**: `pdf_path` у документов не заполняется из карточки заявки.
4. **Нет версий документа** (пересборка сохраняет предыдущую версию).
5. **Нет окна отправки** с выбором файлов, прогрессом по каждому файлу и обработкой частичных ошибок.
6. **Тестов на запись на Диск нет** — нужна проверка на тестовой папке.

## План реализации (по шагам, каждый проверяем)

1. **Проверка записи на тестовой папке.** Тестовая папка на Диске расшарена роботу с правом **Редактор**. Скрипт: загрузить тестовый PDF, перезагрузить то же имя (убедиться, что обновилось, а не задублировалось), прочитать список файлов, удалить тестовый файл. Прод не затрагивается.
2. **Связка в карточке заявки:** кнопка «Собрать документ» → `render.generate()` → `pdf_path` и `rendered_at` в `CLIENT_CLIENT`. Перед этим — проверка `unfilled()`: если есть незаполненные обязательные поля, кнопка выключена и объясняет, чего не хватает.
3. **Кнопка «Отправить на Диск»** → `gCLIENT_write.upload_file()` в `CLIENT.gCLIENT_folder_url`, перезапись по имени, лог в журнал событий, статус `sent` только после реальной загрузки. Ошибки — по каждому файлу отдельно, с повтором.
4. **Окно отправки** по макету: путь к папке, список файлов с галочками и статусами, прогресс по каждому, «Повторить неудачные».
5. **Версии документа** и панель «Источники» со счётчиком полей (по исследованию UI-паттернов).
