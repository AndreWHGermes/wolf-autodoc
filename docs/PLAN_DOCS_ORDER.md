не совпадают с настоящими документами, а «оригинальные примеры» местами лежат наши
же сборки. Нужны: настоящий заполненный документ как эталон для каждого из 16 видов,
HTML-шаблон по этому эталону с метками, и блок памяти — инструкция по документу и
по каждой переменной.

## План (по фазам)

Ф1. Эталоны. Для каждого из 16 видов — настоящий заполненный документ:
- собрать из docs/reference, data/gdrive_cache/client_*, ранее присланных файлов;
- положить в `data/templates/<code>/example_filled.pdf`;
- дубль-эталон в `data/templates/<code>/original_source.pdf` + chmod 444 (не перезаписывается);
- скрипт-сторож: сверяет хэш эталона при старте и при сборке, при расхождении — тревога.
Недостающие оригиналы запросить у заказчика списком.

Ф2. Шаблоны по эталону. Для каждого документа:
- сверить координаты/шрифты/кегль блока с эталоном (конвертация PDF→HTML, скилл pdf-to-html-template);
- расставить метки там, где в эталоне значения;
- убрать мусор и «уехавшие» блоки (d12, cv__format_detailed — пересобрать заново).

Ф3. Блок памяти — инструкции:
- таблица `doc_instructions` в wolf.db: для каждого документа — как заполняется,
  порядок полей, правила (что вводит админ, что система, что ставится руками: METERAI, подпись);
- таблица `variable_instructions`: для каждой переменной — откуда берётся значение,
  формат, регистр, язык, правило выбора (карточка / пул / вычисление / руками);
- скилл `wolf-doc-instructions` — чтобы эти правила применялись в работе;
- экран «Инструкция» в конструкторе: рядом с документом видно, как он заполняется.

Ф4. Приёмка. По каждому документу: сборка на данных клиента, машинная сверка мест
меток и текста с эталоном, визуальная проверка. Только после этого — цикл целиком.

## Порядок работ

1. Ф1 по тем документам, для которых эталон есть в системе (список выше).
2. Список недостающих эталонов — заказчику одним сообщением.
3. Ф2 по одному документу за проход, начиная со сломанных (cv__format_detailed, d12).
4. Ф3 — таблицы и скилл; наполняются по мере прохода Ф2.
5. Ф4 — приёмка и запуск цикла.
