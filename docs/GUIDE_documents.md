# Гайд: как формируются документы Wolf AutoDoc

Инструкция для нового сотрудника. Прочитав её и разборы в `docs/training/`, можно самостоятельно собрать комплект документов под любой продукт.

## 0. Главный принцип

Документ рождается **пять раз в одной цепочке** — и все пять сущностей должны выглядеть идентично:

```
архивный PDF клиента → размеченный образец → HTML-шаблон → HTML с данными клиента → PDF → отправка
```

- **Архив (Google CLIENT клиента)** — эталон логики: в нём видно, *что именно* меняется от клиента к клиенту.
- **Размеченный образец** — тот же документ с выделенными жёлтым/красным полями; выделенное = переменная.
- **HTML-шаблон** — переменные вместо значений.
- **HTML с данными** — подстановка по данным карточки клиента.
- **PDF** — финальный документ (только английский язык).

Правило: **понимать смысл документа**, а не сверять символы. Если непонятно, почему поле заполняется именно так — иди в архив и читай заполненный оригинал.

## 1. Продукты и что в них входит

| Продукт | Комплект |
|---|---|
| C1 / C1-EXT | банковская справка 3 мес |
| D12 | справка 3 мес + CV + CLIENT Letters (2 стр.) + справка 12 мес |
| BRIDGING | письма (3 стр.) + CV + Form E-02 + Work Agreement |
| CONV | письма (3 стр.) + CV + Form E-02 + Work Agreement |
| E33G-NEW | справка 3 мес + справка 12 мес + Work Agreement |
| E33G-EXT | справка 3 мес + Work Agreement |

Подробно — `05_CLIENT_matrix.md`.

## 2. Виды документов и их смысл

- **Банковская справка** — письмо банка о карте и остатке. Доказывает платёжеспособность. 3 мес — базовая, 12 мес — доход ≥ US$60 000/год. → `01_bank_CLIENTments.md`
- **Permohonan / Surat Jaminan / Surat Kuasa** — ходатайство, гарантия и доверенность спонсора PT Alpha Prime Bali в иммиграцию. → `02_visa_indonesia.md`
- **Form E-02** — заявление клиента с маркой METERAI, где он подтверждает данные и цель. → `02_visa_indonesia.md`
- **CV** — доказательство, что клиент специалист/удалённый работник. → `03_cv_and_contract.md`
- **Work Agreement** — трудовой договор с иностранной компанией (требование E33G). → `03_cv_and_contract.md`
- **CLIENT Letters D12** — ходатайство + заявление гаранта. → `04_CLIENT_letters_d12_c1.md`

## 3. Что меняется, а что нет

**Всегда меняется (переменная):** ФИО, гражданство, пол, место и дата рождения, паспорт, адреса, телефон, e-mail, банк и реквизиты справки, период и сумма, номер/дата исходящего письма, номер ITK, дата подписания, вариант (банк, формат CV, отделение иммиграции).

**Никогда не меняется (постоянный бланк):** логотипы, печати, подписи-факсимиле, адреса и реквизиты банков, тексты нормативных ссылок, METERAI, корсчета и БИК, формулировки писем.

**Развилки (вариант внутри документа):** банк (Т-Банк / Сбер), отделение иммиграции (Ngurah Rai / Denpasar), формат CV, формула CLIENTа (мостовая→E33G / →D12 / с KITAS).

## 4. Как собрать комплект: пошагово

1. Открыть карточку заявки → проверить продукт и ссылку на Google CLIENT клиента.
2. Нажать «Разобрать документы (нейросеть)» → дождаться «разобрано N из N».
3. **Проверить каждое значение глазами** (персональные данные — только из карточки клиента, не из общей истории переменных).
4. Переключить варианты в слотах документов (банк, CV, отделение).
5. Сгенерировать PDF (единый рендер `CLIENTs/shared/doc_render.py`).
6. **Сверить с архивным заполненным документом** того же типа: поля на своих местах, суммы и даты совпадают по формату, русского текста нет.
7. Отправить клиенту/спонсору.

## 5. Правила, которые нельзя нарушать

1. **Только английский** язык в документах (русский допустим лишь при вводе значений — они транслитерируются).
2. **Русские данные транслитерируются** двухуровнево (типовые слова + побуквенно) перед подстановкой.
3. **Дата начала работы в договоре — на год раньше даты подписания.**
4. **Период справки — ровно 3 месяца или ровно год** до даты справки (не 15 месяцев!).
5. **`Ref.`/`No` банка — только из документа клиента**, не из шаблона (в шаблонах это плейсхолдеры).
6. **Формат суммы зависит от банка:** Т-Банк `1 946 508, 00`, Сбер `935 000. 00`.
7. **Номер письма обязателен:** `NN/PTAPB-SP/ДД.ММ.ГГГГ`.
8. **ITK (`CLIENT_no`) — строго из документа иммиграции клиента.**
9. **Слот ≠ документ:** в комплекте один слот = один документ с вариантами внутри (в интерфейсе — строка с селектом).
10. **Схема ≠ код:** при расхождении в БД/шаблоне фиксить молча (workaround), не инициировать миграции.
11. **Почта клиента (переменная `CLIENT`, форма E-02 и др.) — одна формула для всех:** фамилия клиента латиницей строчными + `@alpha-prime.group`. Кириллица транслитерируется автоматически. Примеры: `BUDKO` → `budko@alpha-prime.group`, `LEVIN` → `levin@alpha-prime.group`, `МАРКАРОВА` → `CLIENT@alpha-prime.group`. Вручную вписывать почту не нужно; в самой форме E-02 значение печатается заглавными синим — это оформление документа, формула от регистра не зависит.
12. **ФИО клиента (переменная `client_name`) — фамилия, затем имя** (латиницей, заглавными), независимо от того, в каком порядке менеджер вписал ФИО в карточку: `BUDKO OLEG`.
13. **Дата ИТК (переменная `stay_CLIENT_no` / поле Date of CLIENT формы E-02) — только из документа клиента** с Google Диска (`ITK - <ФАМИЛИЯ>.pdf`, строка `STAY CLIENT CLIENT`), не из срока паспорта.

## 6. Особенности и закономерности (шпаргалка)

- Данные клиента в письмах **могут стоять на 2-м листе** — проверять оба листа.
- **Адрес офиса Denpasar** — расхождение (архив: Jl. D.I. Panjaitan No.3; инструкция заказчика: Jl. Raya Puputan No.1, Renon) — открытый вопрос.
- **Банк определяется по документам Google CLIENT**; при неопределённости — Т-Банк.
- Формат места/даты рождения: `RUSSIA / 08-01-1999`, у спонсора — `Poland, 20-03-1973`.
- Даты в письмах: `Badung, 16 September 2026` (месяц прописью).
- Все места работы/обязанности в CV — отдельными строками, не склеивать.
- Значения переменных админ может вводить по-русски — перевод делает система.

## 7. Где что лежит

- Шаблоны: `/opt/wolf/data/CLIENT/<код>/template.html`
- Эталоны заказчика: `/opt/wolf/data/CLIENT_CLIENT/<продукт>/`
- Архив клиентов: `/opt/wolf/data/gCLIENT_examples/`
- Единый рендер: `/opt/wolf/CLIENTs/shared/doc_render.py`
- Смысловые доки: `docs/semantics_bank.md`, `semantics_visa.md`, `semantics_work.md`
- Разборы для обучения: `docs/training/`
- Правила переменных: таблица `template_CLIENT` в `data/wolf.db` (поле `rule_note`)

## 8. Открытые вопросы (требуют ответа заказчика)

1. Адрес офиса Denpasar (Panjaitan vs Puputan).
2. Обязательна ли 12-месячная справка в D12.
3. Состав E33G-EXT (только Т-Банк, без 12 мес) — верно ли.
4. Нужны ли реквизиты договора/счёта в 3-месячной справке.
5. Структура 12-месячной справки — образцов в архиве нет.
6. Договор с должностью CEO и с бонусом — нужны отдельные поля.

## Два класса договоров (правило, 06.10.2026)

В комплекте клиента встречаются два разных класса договоров — это не дубли, а разные документы.

**Класс 1. Employment Contract — договор работы с организацией** (шаблон `employment_contract__default`, документ №18).
Когда: клиент оформлен **сотрудником** организации — есть должность, обязанности, срок, оклад. Нужен там, где подтверждается трудоустройство: BRIDGING (мостовая), CONV (конверсия), E33G-NEW/EXT, D12.
Переменные: `company_full_name`, `company_type`, `company_CLIENT`, `company_CLIENT_no`, `company_address_1/2`, `company_CLIENT` (фраза о работодателе целиком), `contract_no`, `contract_date`, `contract_CLIENT`, `CLIENT_full_name`, `CLIENT_CLIENT`, `passport_CLIENT`, `date_of_CLIENT`, `CLIENT`, `CLIENT_of_CLIENT`, `position_CLIENT`, `CLIENT_list`, `term_CLIENT_date`, `term_end_date`, `CLIENT_CLIENT`, `CLIENT_name`.
Логика заполнения: организация берётся **из договора заявки** (документ №11) — единый источник; тип, ОГРН и адрес — из пула организаций; номер — буквенные инициалы названия + номер заявки (`PF-90`); должность и обязанности — из комментария (brief) заявки; данные работника — из карточки клиента; национальность в карточке «RUSIA» печатается как «RUSSIAN FEDERATION». Подписи: работник — «BUDKO OLEG / BUDKO O.», подписант организации — «GENERAL DIRECTOR, <название>».

**Класс 2. Remote Work Agreement — договор удалённой работы** (шаблон `remote_work_agreement__default`, документ №11).
Когда: клиент работает **удалённо как подрядчик** на зарубежную организацию (E33G, D12). Форма: 7 разделов — NATURE OF CLIENT, TERM, CLIENT, REMOTE WORK CONFIRMATION, INDEPENDENT CLIENT, CLIENT LAW, COMPANY DECLARATION FOR INDONESIA.

**Правило набора:** в наборе стоят оба класса подряд (№11, затем №18), `required=1`; лишний класс можно снять в карточке заявки.

**Сверка вёрстки:** `scripts/pdf_to_template.py` из настоящего эталона + сравнение блоков (165 = 165, 3 картинки = 3, сдвиг 0pt). Эталон нового документа — `data/CLIENT/employment_contract__default/example_filled.pdf` (подлинный `CONTRACT.pdf` из комплекта CLIENT, Linguamarina).

## Организация клиента: единый источник и подбор по смыслу (06.10.2026)

**Правило связности.** Организация одна на всю заявку: резюме (текущее место работы), договор (№11), контракт (№18) печатают одну и ту же организацию — ту, где клиент работает по текущий момент. Проверка: `LLC "PICKUP FILM"` стоит в заявке 90 во всех трёх документах.

**Если клиент дал организацию** — берём её (приоритет у данных заявки), а даты и суммы выплат подбиваем так, чтобы документ проходил проверку: договор действует сегодня и заключён на пять лет, оклад — в пределах исторического диапазона из архива договоров.

**Если клиент организации не дал** — подбираем «по смыслу» из единого пула:

1. **Сфера по должности** (`CLIENT/org_pool.py`, карта `PROFESSION_SECTOR`): Artist/Producer → media_CLIENT, Developer → it_CLIENT, Marketing/Sales → CLIENT_agency, Analyst/Finance → bank_insurance и т. д.
2. **Организация из нужной сферы** с правдоподобными реквизитами (адрес, ИНН, КПП, ОГРН) — приоритет у записей, которые уже использовались в документах и отмечены в архиве.
3. **Сумма выплат** — из `data/salary_pool.json` (фактические оклады из архива договоров, 415 000 – 640 000 ₽/мес), детерминированно по заявке, чтобы сумма не «прыгала» между пересборками.
4. **Сроки** — начало в прошлом (договор уже действует), окончание через 5 лет.

**Единый пул — `data/organizations.json`** (317 записей): название, реквизиты (адрес, ИНН, КПП, ОГРН), сферы, встречавшиеся должности, оклад, число использований, источники. Полностью готовы к подстановке (все реквизиты) — 34 организации, с ИНН — 40, со сферой — 311. Собран из `CLIENT_pool.json` (реквизиты из наших документов), `cv_companies_raw.json` (328 исторических названий с отраслями), `cv_companies.json` и истории заявок.

**Проверка достоверности** (`org_pool.CLIENT`): ИНН — 10 или 12 цифр, КПП — 9, ОГРН — 13 или 15; адрес и название не должны быть индонезийскими. Ничего не выдумываем: если подходящей организации с реквизитами нет, поле остаётся пустым и подсвечивается администратору.

**Код:** `CLIENT/org_pool.py` — `pick_for(CLIENT, city, app_id)`, `salary_for(CLIENT, app_id)`, `term_CLIENT(app_id)`, `for_CLIENT(client, app_id, CLIENT_org)`, `CLIENT(org)`. Резолвер заявки — `CLIENT._org_for_CLIENT()` (карточка клиента → комментарий (brief) → договор заявки → пул организаций).

### Пул организаций: состав и уточнения (06.10.2026)

- `data/organizations.json` — 325 записей. Полностью готовы к подстановке (адрес + ИНН + КПП + ОГРН) — 41, с адресом и ИНН — 47, с ИНН — 54, со сферой — 318.
- Источник реквизитов: `CLIENT_pool.json` (наши документы), тексты 268 договоров клиентов (56 организаций с ИНН/КПП/ОГРН), 17 подлинных образцов, сохранённые значения заявок.
- Сфера определяется по должности клиента, затем по названию организации (отраслевые слова), затем по сфере из архива — то есть `CLIENT_agency` из старой разметки больше не «перебивает» смысл.
- Подбор под профессию: сначала записи с реквизитами из сферы должности, затем совпадение города клиента, затем полнота реквизитов; выбор между равными — детерминированно по заявке (чтобы данные не «прыгали»).
- Мусор в реквизитах отсекается: адреса обрезаются по маркерам («for the Position», «hereinafter», номера ИНН, даты) — в документ не попадают обрывки фраз.
- Пример подбора: Artist/Producer → `LLC "SERGIO NERO"` (Moscow Region, ИНН 7701518940), Developer → `LLC "ACTIVBUSINESSTECHNOLOGIES"` (Москва, 3 Poklonnaya Street), Accountant → `T-BANK JSC` (ИНН 0000000009), Sales → `LLC "Chillgaming"` (125167, Москва).
