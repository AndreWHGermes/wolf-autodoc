# services/values/ — источники значений

Здесь живёт логика **откуда берётся каждое значение**, которое подставляется в документ.
Разбито по доменам: персональные данные, адреса, организация, финансы.

`orchestrator.py` — единая точка входа (бывший `services/values.py`), которая собирает
значения из всех источников по конкретному шаблону.

## Принцип

- Один файл = одна зона ответственности (ФИО / адрес / финансы / организация).
- Импорт шаблонных правил — через `services/templates/registry.py`.
- Кэширование (`application_documents.values_json`) — отдельный модуль `cache.py`,
  с явной политикой «пересчитать» / «ручная правка — не трогать».

## Структура

```
services/values/
├── personal.py           — ФИО, паспорт, даты рождения, гражданство
├── addresses.py          — адреса РФ / Индонезия
├── organization.py       — работодатель (пул + выбор)
├── finance.py            — суммы, остатки, пропись
├── contracts.py          — даты договоров, стороны
├── orchestrator.py       — точка входа: build_template_values()
├── cache.py              — работа с values_json (политика пересчёта)
└── registry.py           — связь «переменная → источник»
```

## Кто сюда пишет

- Новая категория значений → новый файл в этом каталоге.
- Новая переменная → регистрация в `registry.py` + паспорт в `data/variables/<name>.yaml`.

## Кто импортирует

- `services/autofill.py` — собирает значения перед рендером.
- `services/templates/*` — запрашивают значения своего бланка.
- `blocks/review/page.py` — показывает значения в форме редактора.
