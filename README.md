# Wolf AutoDoc — CRM визового агентства с агентом-исполнителем

Публичная (обезличенная) копия рабочей системы визового агентства на Бали.
Система готовит комплекты документов для иммиграции Индонезии (KITAS E33G remote worker,
bridging visa, конверсия ITK → KITAS, продление), а также банковские справки, договоры,
резюме и заявления (FORM E-02).

## Чем этот продукт отличается от обычной CRM

Обычная CRM — инструмент для менеджера: человек заводит клиента, заполняет поля, жмёт кнопку.
Здесь в центре цикла **агент**: он читает заявку, собирает документы, подставляет значения,
проверяет целостность и следит за сроками. Веб-интерфейс — для контроля, правок и выпуска.

Роль агента описана в `AGENT_ROLE.md`, устав — `docs/AGENT_CHARTER.md`.

## Структура

```
app.py                  точка входа веб-приложения (Flask)
core/                   конфиг, БД, безопасность, права, локализация
services/               бизнес-логика: значения документов, рендер, автозаполнение,
                        Google Drive, распознавание сканов, счётчики, сроки
blocks/                 HTML-блоки интерфейса и печатные формы
repositories/           доступ к данным
blueprints/             маршруты веб-приложения
bot/                    Telegram-бот системы
scripts/                инструменты: пересборка шаблонов, сверка, проверки, миграции
migrations/             миграции схемы БД
tests/                  тесты
docs/                   документация, правила предметной области, аудиты
docs/reference/         канон агентства: типы виз, документы и поля, правила легенды
```

## Запуск

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-system.txt      # Flask, WeasyPrint, PyMuPDF, python-docx и др.
export WOLF_DB=./data/wolf.db               # путь к базе (создаётся при первом старте)
python3 app.py                              # веб-интерфейс, порт из WOLF_PORT (по умолчанию 8091)
```

Печать PDF выполняется через WeasyPrint (HTML → PDF), сборка .docx — из того же дерева блоков.
Секреты (токены ботов, ключи Google, доступы к почте) в репозитории отсутствуют — задаются
переменными окружения.

## Что сознательно НЕ входит в публичную копию

- персональные данные клиентов: сканы паспортов, справки, выписки, база данных;
- рабочие шаблоны печатных форм с фоновыми изображениями и образцами документов;
- ключи, токены, сертификаты и резервные копии.

Всё перечисленное остаётся в рабочем контуре; публичная копия содержит код, логику и
документацию, очищенные от персональных данных.

## Известные проблемы и точки роста

Список задач, с которыми мы сталкиваемся каждый день, — в `PROBLEMS.md`. Он составлен как
техзадание для доработки: каждая проблема с указанием причины и места в коде.

## Что нового (16.10.2026)

- **Главная = экран входящих.** Блок «Автоматика» (Старт / Пауза) по центру шапки;
  каждая заявка — одна компактная строка: номер, клиент, продукт, менеджер, статус.
- **Управление очередью.** Заявку можно поставить в работу, остановить или убрать в архив;
  очередь идёт строго по одной заявке, параллельные прогоны запрещены.
- **Прогресс заявки.** В карточке видны этап («в очереди», «обрабатывается · этап»),
  ошибка с причиной и итог «отправлено на Диск». Этапы раскрываются списком.
- **Журнал этапов.** Единая лента по 12 этапам: приём, взятая в работу, продукт, набор
  документов, чтение Диска, чтение заявки, легенда, заполнение, визуальная проверка,
  логическая проверка, отправка, готово. У каждого шага — исполнитель, время и причина сбоя.
- **История.** Строка: номер → клиент → менеджер → продукт → метки (архив / на Диск / ошибка);
  по номеру открывается полный ход заявки.
- **Метки «тест» и «тест с реальными данными»** убраны: осталась только метка «архив».
- **Уведомления.** Менеджеру — «принята», «взята в работу», «документы готовы»;
  администратору — новая заявка, ошибка с пояснением и готовый пакет со ссылками.
